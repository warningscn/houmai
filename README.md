# houmai（候脉）

Codex 任务额度耗尽后的自动值守：等额度窗口重置，再以原轮次的上下文（模型、工作目录、思考强度、审批、沙箱策略）把中断任务接回。只处理额度耗尽这一类中断。

## 特性

- **自动恢复**：额度窗口重置后，按原轮次的上下文（模型、工作目录、思考强度、审批、沙箱策略）把中断任务接回，无需手动介入。
- **双通道、按来源分流**：桌面端发起的会话只走桌面直跑通道（跟随者身份接入，不抢写锁）；CLI 发起的会话直接走命令行 `codex exec resume`。
- **长 / 短周期都管**：小时级与周级额度耗尽都排期续跑，而不只是提醒。
- **本地只读面板**：浏览器查看值守状态与日志，不触发任何续跑。
- **零第三方依赖**：纯 Python 标准库，运行环境独立，克隆即可运行。

## 安装

**支持范围：仅 Windows。** 值守依赖计划任务、`.vbs` 隐藏启动器与 PowerShell，其它平台目前不可用（Python 侧的判定逻辑本身与平台无关，但入口链是 Windows 专属）。

前置条件，缺一不可：

| 需要 | 说明 |
| --- | --- |
| 独立安装的 Python 3.9+ | **不要**用随其它应用分发的运行时——看护工具若跟着被看护对象一起消失，比没有值守更糟。`py` 启动器可用最省事（它只认识真实安装的 Python） |
| Node.js + Codex CLI | `codex` 能在 PATH 中找到，且已用账号登录 |
| `~/.codex` 下已有会话记录 | 没有会话就没有东西可守 |
| 联网 | 续跑要连得上 Codex 后端。注意 **codex 不读取环境变量里的代理设置**，它走系统代理 |

步骤：

1. 取得项目（克隆或解压）到**任意目录**，目录名带空格也可以——脚本全部从自身位置推导路径。
2. （可选）**无需手动复制**——首次运行会自动基于 `config.example.json` 生成 `config.json`。想定制再编辑它；不生成也能直接跑，程序用内置默认值。
3. **建议**：编辑 `config.json` 的 `codex.avoid_paths`，填上"随其它应用分发的解释器／Node"所在目录的子串（子串匹配，大小写和斜杠不敏感）。凡路径命中这份清单的运行时一律**拒用**，与 PATH 顺序无关；默认为空，等于没有这道防线。
4. 自检两道，都过了再注册：

   ```cmd
   py -3 tests\smoke.py
   py -3 src\houmai.py check
   ```

   前者应当全绿（断言数见 [测试](#测试)）；后者会报出它实际选中的解释器、Node、Codex 入口，并给出"是否可以值守"的结论。
5. 双击根目录的 `houmai.cmd`，选 **3** 注册计划任务。

**想要在任意目录敲 `houmai`**：把项目的 `scripts` 目录加进 PATH 即可（`scripts\houmai.bat` 是唯一入口）。也可以在你自己习惯的目录放一个转发脚本——那种私有配置不需要进版本库，也不影响本工具的运行。

## 快速开始

双击根目录的 **`houmai.cmd`**：

| 选项 | 作用 |
| --- | --- |
| 1 | **后台启动面板**（无窗口，自动打开浏览器，`http://127.0.0.1:8787/`） |
| 2 | 停止面板（三种结果：已停止／**本来就没有面板在运行**／未能确认——后者会停住等你按键） |
| 3 | **注册值守计划任务**（每 10 分钟无窗口运行一轮；重复执行安全，安装与修复都用它），完成后自动启动面板 |
| 0 | 关闭本窗口（不做任何操作） |

辅助脚本在 `scripts\`，日常不用碰。

## 常用命令

`scripts\houmai.bat` 是 Python 侧的**唯一入口**（解释器独立性检查只在这里做），下面所有命令都由它转交。想在任意目录直接敲 `houmai`，见上文[安装](#安装)最后一段。

| 命令 | 作用 |
| --- | --- |
| `houmai web` | 值守面板（浏览器，只读） |
| `houmai stop` | 停止面板（值守不受影响） |
| `houmai health` | 体检：一条命令判断值守是否正常 |
| `houmai netcheck` | 连通性检查：续跑时连不连得上 Codex 后端 |
| `houmai log` | 看值守日志（`-n 100` 指定行数，`--all` 看全部） |
| `houmai check` | 自检：CLI 版本、会话目录、配置、运行时 |
| `houmai status` | 在册任务、下次续跑时间、最近记录 |
| `houmai run` | 执行一次值守（计划任务调用的就是它） |
| `houmai run --dry-run -v` | 演练：只判定不发送，状态 / 尝试次数 / 事件都不动 |

## 面板

- 每 5 秒自动刷新；检查卡片只报需要留意的事，异常时给出具体问题与修法。常态卡还会顺带说明**这项是干什么的**（例如「计划任务」卡写明它每 10 分钟无窗口跑一轮值守），失败卡只给修法。
- 顶部徽标「值守正常」只表示**值守机制本身健康**（Codex、计划任务、电源策略、运行时、上次值守这五项）；若有待人工处理的任务（候脉已放弃续跑），徽标下方会多一行**琥珀色「有 N 个任务需人工处理」**——两层含义分开看，别被绿字误导。任务卡状态胶囊：`等待窗口重置`／`重试中`／`续跑待确认`／`仅提醒不续跑`／`已接回`／`放弃续跑`／`任务已自行继续`；终态卡不再显示已过期的「续跑时间」。
- 事件表至多展示**最新 10 条**（新在上，超出时标题注明）；底账 `events.jsonl` 永不删改。
- 面板只读（不触发续跑）、只监听 `127.0.0.1`。
- 停止：页面右上角按钮，或 `houmai stop`。停止后页面上的按钮会变成「启动面板」，点击即可重开（依赖 `houmai://` 协议，选 3 注册时自动安装；首次启动浏览器会询问是否允许）。想在控制台里**守着看**面板输出（关窗即停），在任意窗口敲 `houmai web`：返回 `0` = 正常停止，`2` = 端口没监听上（面板没起来），`3` = 没找到合规解释器。
- 端口被占说明已有面板在跑：先 `houmai stop` 再开，或 `houmai web --port 8788`。
- 改 `config.json` 刷新页面即生效；改面板模板 `src\panel.html`（文案/样式/前端逻辑）也是**刷新即生效**；只有改后端代码（`houmai.py` 的判定/扫描逻辑）才需重启面板进程。

## 在哪里看

| 想知道 | 在哪看 |
| --- | --- |
| 一眼看整体 | 面板（`houmai.cmd` 选 1） |
| 值守跑没跑、正常不正常 | `houmai health` |
| 每一轮具体做了什么 | `houmai log` |
| 原始日志 | `state\run.log`（超 512 KB 自动轮转到 `run.log.1`） |
| 菜单／注册动作的完整输出 | `state\install.log`（选 1／选 2／选 3 每次追加一段，带时间戳段头） |
| 在册任务与下次续跑时间 | `houmai status` |
| 结构化历史事件 | `state\events.jsonl`（追加式，永不删改） |

`state\install.log` 是纯追加的文本，记录每次从菜单发起动作时屏幕上出现过的全部内容（含失败时的退出码）。它随时可以整个删掉——删了只丢历史记录，不影响任何功能。

## 值守是否正常

跑 `houmai health`，任一为 ✗ 才需要动手：

| 检查项 | 正常表现 | 不正常怎么办 |
| --- | --- | --- |
| Codex CLI | ✓ 版本 ≥ 0.150.0 | `npm i -g @openai/codex@latest` |
| 计划任务 | ✓ 已注册（卡片写明：每 10 分钟无窗口跑一轮，检查额度中断并续跑） | `houmai.cmd` 选 3 |
| 计划任务电源策略 | ✓ 不受电池限制 | 笔记本拔电后任务不启动，`houmai.cmd` 选 3 重注册（注册脚本会自动关掉该限制） |
| 上次值守时间 | 距今 25 分钟内 | 任务没在跑，`houmai.cmd` 选 3 重注册 |
| 结论行 | "值守正常"；有待人工任务时下方另出琥珀提示 | 徽标只报机制健康，按上方 ✗ 处理；琥珀提示的任务进 `state\events.jsonl` 看 `abandoned` 的 `reason` |

- 没中断时"近 24 小时"显示"无事件"是正常的；判断"在跑"看**上次值守时间**。
- "等待中"的任务是正常业务状态（额度窗口没到重置点），不是故障。

## 计划任务

- 注册：`houmai.cmd` 选 3（内部调 `scripts\install-task.cmd`）。创建名为 `houmai` 的任务，每 10 分钟经 `scripts\run-hidden.vbs` 无窗口运行一次。
- **电源策略**：Windows 默认给新任务勾选"不用电池启动 / 改用电池时停止"，笔记本一拔电值守就静默停摆（任务仍显示"已启用"，体检也查得到）。所以注册时**一步建好**：任务的动作、触发器、设置（含电源策略）由 `scripts\register-task.ps1` 在同一次调用里一起提交，不存在"先建任务、再打补丁"的时序窗口；注册后回读校验，仍受限即以非零码退出并给出手工修法。体检里的"计划任务电源策略"一项负责在异常时报出来。
- **`houmai://` 协议**：面板页的「启动面板」按钮靠它拉起面板，选 3 时顺带安装（写 `HKCU\Software\Classes\houmai` 的三处值）。`reg add` 对不存在的键是"没有就建"，所以**键缺失本身会自愈**；它给不了的保证是"究竟写进去没有"——三条调用都把输出丢进 `nul`、返回码**有意不看**。因此注册完**回读注册表复核三处**：① `URL Protocol` 标记 ② `(默认)` 显示名 `URL:houmai panel launcher` ③ 处理器指向**本副本**的整条路径（只核文件名的话，项目搬家后指向旧路径的失效值也会被判为正常）。任一不符 → `[WARN]`，并给出期望路径与"改用选 1"的兜底。任务本身没注册成功时，协议段会被整段跳过，`[FAIL]` 里会说明这一点。
- 卸载（低频）：`scripts\uninstall-task.cmd`，或 `schtasks /Delete /TN "houmai" /F`。删除任务即完全停用，项目文件与本地记录不受影响。
- **注册窗口怎么收尾**：全部成功时窗口 5 秒后自动关闭（按任意键可提前关）；**一旦出现 `[WARN]`／`[FAIL]` 就停住**，等您按任意键再关——注册结果只在屏幕上出现一次，不让它跟着定时器一起消失。想完整看一遍输出，可在已打开的 cmd 窗口里手动运行 `scripts\install-task.cmd`（窗口不会消失）。

## 提醒通道

默认只写本地记录（`notify.provider` 为 `none`）。要推送微信，编辑 `config.json`：

```json
"notify": {
  "provider": "serverchan",
  "serverchan_key": "<Server酱 SendKey>",
  "on": ["detect", "success", "failure", "long_cycle"]
}
```

同一任务同类提醒 6 小时内不重复推送。

## 配置项

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `codex.command` | `null` | 自定义 codex 命令前缀，留空自动探测 |
| `codex.node` | `null` | 指定 node 可执行文件，留空自动探测 |
| `codex.avoid_paths` | `[]` | 硬排除清单：绝不复用这些目录下的运行时（本机在 `config.json` 里已排除被看护程序自带运行时） |
| `codex.env` | `{}` | 额外传给 Codex 子进程的环境变量（codex 不读 env 代理变量，这里配代理只影响 `netcheck` 的探测列） |
| `codex.codex_home` | `null` | 默认 `~\.codex` |
| `codex.min_version` | `0.150.0` | 低于此版本拒绝值守 |
| `watch.ignore_threads` | `[]` | 不接管的任务 ID 清单 |
| `watch.lookback_days` | `3` | 扫描最近几天的会话记录 |
| `watch.silence_minutes` | `5` | 会话静默多久才允许续跑，避免与客户端并发写 |
| `watch.initial_lookback_hours` | `12` | 首次运行时，早于此的中断只记为历史，不接管 |
| `retry.prompt` | `continue` | 续跑指令 |
| `retry.channel` | `auto` | 续跑通道：`auto` 按会话来源分流；`ipc` 只用桌面通道；`exec` 只用命令行。**按会话来源分流**：桌面端（Codex Desktop）发起的会话只在桌面通道续跑、绝不兜底到命令行——否则命令行会抢走写锁，桌面再打开就报"已在另一个应用中打开"；CLI（`codex-tui`）发起的会话直接走命令行，不试桌面。`channel=exec` 配置可强制覆盖来源（连桌面会话也走命令行） |
| `retry.buffer_seconds` | `120` | 窗口重置后再等多久才发 |
| `retry.max_attempts` | `3` | 同一任务最多尝试次数 |
| `retry.backoff_seconds` | `[0,600,1800]` | 失败退避间隔（秒）。按**轮巡粒度**生效：值守每 ~10 分钟唤醒一次，小于轮巡间隔的退避即"下一轮重试"；`0` = 下一轮立即重试。默认的真实节奏：下一轮、再等一轮、再等三轮 |
| `retry.coalesce_minutes` | `10` | 窗口内重复信号合并为一次 |
| `retry.confirm_deadline_minutes` | `30` | 续跑已发出但未确认新轮次时，最多复查多久；超时转人工 |
| `retry.resume_long_cycle` | `true` | 长周期额度（周及以上窗口）是否也排期续跑；关掉即回退到"只提醒" |
| `retry.max_wait_days` | `8` | 长周期等待上限（天）：重置时间超出则退回仅提醒；`0` = 不设限 |
| `panel.history_days` | `3` | 历史记录展示窗口（天），只影响展示，底账不删 |
| `panel.show_skipped_stale` | `false` | 是否展开"历史中断跳过"记录 |
| `state_dir` | `state` | 状态与记录目录 |

## 数据与边界

- 状态与记录：`state\state.json`、`state\events.jsonl`（追加式事件底账）、`state\run.log`（超 512 KB 轮转）。
- 面板只监听 `127.0.0.1`，只读上述文件，无写操作、无续跑入口。
- 只读 Codex 会话记录与配置，不改写任何 Codex 文件。
- 续跑逐字段复刻原轮次策略，**不提升权限**；续跑会重发会话上下文，产生真实用量。
- 桌面窗口直跑通道（`retry.channel=auto` 默认开启）：会话正被 Codex Desktop 打开时，
  通过桌面本机 IPC 总线以跟随者身份向原窗口送达「继续」，绕开单写者锁；
  回执超时不计失败，按「未确认」核对，绝不重复投递。该通道依赖桌面端内部 IPC 协议（实验性），Codex 升级后如失效会自动回落 exec 并记日志。
- **续跑通道按会话来源分流**（关键，避免写锁被夺）：会话的发起端（`session_meta` 里的 `originator`）决定兜底策略——
  CLI（`codex-tui`）发起的会话**直接走命令行，不试桌面**（它本就没在桌面开着，试桌面只会空耗一轮 IPC 握手再回落）；**桌面端（Codex Desktop）发起的会话只在桌面通道续跑，绝不兜底到命令行**。
  原因：命令行 `codex exec resume` 会取得会话的写锁，一旦桌面端之后再打开该会话便报「已在另一个应用中打开」。
  桌面端会话本就该回到桌面，所以桌面此刻接不住（桌面没运行 / 未持有该会话）时，候脉**留到下一轮再试**，而不是把会话抢过去。
  面板任务卡会显示「来源：桌面版 / CLI」一行，便于确认分流是否如预期。
  注：`retry.channel=exec` 配置会覆盖来源，强制全部走命令行（包括桌面会话）。
- 长周期额度（周及以上）默认也排期续跑；`retry.resume_long_cycle` 关闭、或重置时间超出 `retry.max_wait_days` 时退回仅提醒。
- 在册任务只保留活跃项：已接回／已自行继续的任务次一轮自动摘除；放弃续跑／仅提醒的任务过 `retry.resolved_retention_days`（默认 7 天）后摘除，任务卡会标注「保留至某时刻」。每次摘除都记 `pruned` 事件（面板事件表可见），审计底账不受影响；被摘轮次按 `turn_id` 记忆，同会话之后的新中断照常接管。
- 运行时必须独立安装（`codex.avoid_paths` 排除被看护程序自带运行时）；异常时 `check` / `health` / 面板卡片 / run 日志四处都会报。

## 测试

```cmd
py -3 tests\smoke.py
```

235 项断言，全部使用构造数据，不触碰真实 Codex；测试数据必须照真实会话格式写。**这个数字由用例自己校验**：最后一条断言会把它和实际条数比对，写错就红。

用 `py -3`（项目规范解释器）运行。反过来说，**别用受限目录里的解释器跑**（被 `codex.avoid_paths` 排除的那些）——用例 7 会因此**故意**失败，那是设计而非故障。

`tests\e2e_real.py` 会发起真实续跑，需显式授权（`HOUMAI_E2E_SESSION` / `HOUMAI_E2E_CWD` / `HOUMAI_E2E_MODEL`），默认不运行。

## 排障

| 现象 | 处理 |
| --- | --- |
| 续跑报网络错误 / `netcheck` 不通 | 检查系统代理是否开着（codex 联网走系统代理，不读 env 代理）；可用 `netcheck` 复核 |
| 面板改了 `config.json` 不生效 | 刷新页面即可；改面板模板 `panel.html` 同样刷新即生效；改后端代码才需重启面板 |
| 体检报「解释器 / Node 来自受限目录」 | 双击 `houmai.cmd` 选 3 重新注册（任务会走固定解释器）；手动跑命令时不要直接调某个 python |
| 拔电后不再值守 / 任务显示已启用却没跑 | 计划任务的默认电池限制所致：`houmai.cmd` 选 3 重注册即可关掉（体检的"计划任务电源策略"会报此问题）。若重注册后仍未消失，注册窗口会打一行 `[WARN]`——按提示到 `taskschd.msc` → `houmai` → 属性 → **条件**，取消"只有在计算机使用交流电源时才启动任务"与"如果计算机改用电池电源，则停止" |
| 面板打不开 / 端口被占 | 已有面板在运行：先 `houmai stop` 再开，或换端口 `--port 8788` |
| 面板显示"连不上值守进程" | 面板被停了，`houmai.cmd` 选 1 重开 |
| 选 2 报 `Stop did NOT confirm` | 面板可能还在跑（进程被占用或权限不足）：重试选 2，或到任务管理器结束那个 python 进程；原始输出在 `state\install.log` 里。反之若报「本来就没有面板在运行」，那是**无事可做**，不是故障 |
| 点「启动面板」按钮没反应 | `houmai://` 协议没注册（按钮靠它拉起面板）：`houmai.cmd` 选 3 重注册；也可先用选 1 启动。选 3 会回读注册表复核三处（`URL Protocol` 标记 / `(默认)` 显示名 / 处理器的**完整路径**），复核不过会打 `[WARN]` 并列出期望路径。首次点击浏览器会弹一次"是否允许打开"，要点允许 |
| 计划任务跑过但看不到输出 | 正常——后台无窗口，用 `houmai log` 看 |
| 日志文件不存在 | `run` 还没跑过；手动 `houmai run --dry-run` 生成 |
| `check` 报版本过低 | `npm i -g @openai/codex@latest` |
| 一直"本轮跳过" | 目标会话仍在写入，等下一个周期 |
| 续跑失败并放弃 | 看 `state\events.jsonl` 中 `abandoned` 记录的 `reason` 与 `tail` |
| 想临时停掉某个任务 | 把任务 ID 加入 `watch.ignore_threads` |
